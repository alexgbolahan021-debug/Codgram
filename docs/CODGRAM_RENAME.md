# Codgram Identity Migration

Codgram is the official product, package, browser, API, runtime, test, log, documentation, and environment-variable identity for this codebase. The supported local configuration names use the `CODGRAM_` prefix. During the V1 migration window, legacy `CORTEX_` variables are accepted only as lower-priority fallbacks; see the main README for the supported replacements.

## Managed workspace metadata

The active managed workspace still resides at `/home/ubuntu/Cortex`, and its managed-project metadata retains the original workspace label. This location is controlled by the hosting workspace and is not safely renamed by changing project source files. The live application, browser title, package name, dashboard, API namespace, runtime modules, settings, logs, and documentation now use Codgram.

## Repository rename

The current Git `origin` is a managed artifact remote rather than a GitHub remote, so renaming a GitHub repository from this active environment would not update the source remote safely. If the original GitHub repository remains named `Cortex`, rename it manually in GitHub under **Settings → General → Repository name**, or from a local clone whose `origin` is the GitHub URL:

```bash
gh repo edit OWNER/Cortex --name Codgram
git remote set-url origin https://github.com/OWNER/Codgram.git
```

Replace `OWNER` with the repository owner. After the rename, refresh any local clones and deployment integrations that still use the old GitHub URL.

## Generated scaffold snapshot

`template.json` is an inactive, framework-generated scaffold snapshot rather than Codgram’s active runtime or deployment configuration. It retains historical template strings and is deliberately not rewritten wholesale, because replacing embedded generated content could desynchronize it from the managed scaffold. It is excluded from product behavior and should be regenerated by the hosting framework if a refreshed template snapshot is required.
